# OlaPay Reference Feature Inventory

Inspection date: 2026-10-08
Source: user-authorized signed-in browser session at `app-web.app-olapay.com`.

This inventory records observed product structure and interaction types. It deliberately omits account identifiers, contact details, invite codes, payment addresses, transaction amounts, and other account-specific content.

## Shared states and cross-cutting requirements

- Provide explicit loading skeletons, empty states, recoverable errors, and success feedback for every data-backed route.
- All wallet and commission values are server-derived; never trust client-supplied balances, exchange rates, bonus ratios, or order totals.
- Implement payment integrations behind interfaces and use a local mock provider by default. Production integrations require owner-supplied configuration.
- The reference is a phone-width web application at the inspected viewport, with a persistent five-item bottom navigation. Larger screens should preserve this app canvas and add safe margins rather than stretching financial cards.
- Routes observed: `/login`, `/`, `/deposit`, `/payment`, `/team`, `/me`, `/account`, `/rechargeHistory`, `/tokenHistory`, `/help`.
- Uninspected or deliberately untouched: password recovery submission, password/PIN resets, Google Auth enrollment, adding/changing UPI accounts, Receive Payment, Send Payment, Buy actions, transaction confirmation/receipt, logout, and any private endpoints.
- Local mock identity and seeded data must be fictional. Never reuse reference account credentials, real identifiers, payment addresses, transaction rows, invite codes, or private data.
